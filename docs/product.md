# 产品范围

本文记录 Wardrobe Mate 的产品构想和建议范围，供后续讨论使用。文中能力均未实现，MVP 范围仍待确认。

## 产品目标

让用户更清楚自己有什么衣服，更容易组合已有衣物，并能结合当天的环境和安排作出穿搭决定。

初期优先验证三个问题：衣物录入是否省事、手动搭配是否顺手、推荐是否值得穿。减少重复购买和提高衣物利用率是预期价值，需要通过真实使用验证。

## 核心流程

1. 拍照或从相册导入衣物，获得适合整理和搭配展示的图片。
2. 查看 AI 提供的属性建议，确认或修正分类、颜色和风格等信息。
3. 浏览自己的数字衣橱，维护衣物信息及是否可穿。
4. 在画布中组合衣物，保存搭配或导出穿搭图片。
5. 根据天气、场景和个人偏好获取建议，也可以锁定单品后调整搭配。
6. 记录实际穿着和反馈，为后续推荐提供依据。

## 建议 MVP 范围

| 范围 | 预期行为 |
| --- | --- |
| 衣物导入 | 支持拍照或相册导入，能够检查并确认处理结果 |
| 衣物整理 | 支持分类浏览、编辑信息和维护衣物可用状态 |
| AI 属性建议 | 提供分类等属性建议；用户始终可以修改，识别失败时允许手动录入 |
| 手动搭配 | 支持拖拽、缩放、旋转、层级调整，以及保存和再次编辑 |
| 搭配导出 | 将保存的搭配导出为图片 |
| 日常推荐 | 结合天气、场景、偏好和可用衣物给出可调整的搭配建议 |
| 局部替换 | 保留指定单品，并调整其他搭配部分 |
| 穿着反馈 | 记录穿着日期、关联搭配，以及喜欢与否、体感是否合适等反馈 |

首版推荐的价值来自对个人衣橱的理解，不以接入多少模型或积累多少外部素材作为目标。

## 体验原则

- 用户确认后的衣物信息是后续整理和推荐的依据，AI 输出属于可修改的建议。
- 推荐只使用用户实际拥有、未移除且当前可用的衣物，不凭空补出单品。
- 候选不足时明确说明，并允许用户调整条件或手动搭配。
- 保留用户锁定的单品；无法组成合适搭配时说明原因，交由用户调整。
- 推荐需要考虑天气和个人体感差异，用户可以覆盖系统建议。
- 图片处理或 AI 识别失败时，可以重试或改为手动录入。
- 天气获取失败或用户不授权定位时，允许手动选择城市或相关条件。
- 外部推荐能力暂时不可用时，仍可使用基本衣橱和手动搭配能力；完整离线体验另行评估。

## 暂不纳入 MVP

- 真人虚拟试穿、生成式褶皱抚平等高成本图像生成功能。
- 自训识别模型、自建 GPU 推理服务。
- 自动采集电商、社交平台或其他第三方穿搭素材。
- 社区内容流、电商交易和复杂社交关系。
- 会员订阅、点数计费和完整商业化体系。

## 后续探索

以下方向需要在核心体验得到验证后再决定是否投入：

- 用个人衣橱中的相似单品复刻参考图穿搭。
- 根据穿着记录和反馈逐步调整个人偏好。
- 衣物穿着频率、闲置情况和单次穿着成本回顾。
- 来源明确、可用范围清晰的穿搭参考与抽象搭配模板。
- 按实际需求评估虚拟试穿等增值能力。

这些方向不构成实施承诺，也不预设上线时间。

## 判断 MVP 是否有价值

- 用户能够完成一组真实衣物的录入、检查和修正。
- 用户能够独立组合、保存、再次编辑并导出一套搭配。
- 推荐能够使用衣橱内可用的真实衣物，并让用户理解和调整结果。
- 锁定单品后，用户仍能完成一次有效的局部替换。
- 失败场景能够清楚呈现，并提供继续完成任务的路径。
- 用户愿意记录穿着或反馈，并在后续再次使用产品。

具体数量、成功率、响应时间和成本指标，需要结合原型及真实样本确定。

## 隐私与素材边界

衣物照片、位置和身材偏好信息按实际需要采集。定位和身材信息不应成为整理衣橱的强制前提。

接入第三方 AI 或图像服务前，应明确哪些数据会离开设备、用于什么目的，以及保存和删除边界。删除衣物时还应考虑关联图片、历史搭配和外部处理数据的关系。

如果后续引入外部穿搭素材，应先确认来源和可用范围。提取抽象搭配规律本身不代表已经解决素材授权问题。

## 待确认问题

- 首发平台是 iOS、Android，还是同步支持两端？
- 初期更优先验证衣物录入、搭配画布，还是每日推荐？
- 首发面向哪个地区，预期用户规模和可接受的外部服务预算是多少？
- 用户是否必须注册，衣物和搭配是否需要跨设备同步？
- 对定位、身材信息和云端图片处理分别提供哪些选择？
- 项目后续采用什么许可证和协作方式？

这些问题在进入工程设计前确认；本文不包含接口、表结构、算法参数或实施任务拆解。
